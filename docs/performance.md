# 性能边界、理论参数与测量（0.3.0）

核对日期：2026-11-02。本页区分代码中的硬限制、实现预算、复杂度分析、历史实测和未来目标。所有数字都有适用范围；没有“任意机器支持多少节点”的单一保证。

## 1. 当前实现参数

| 参数 | 当前值 | 含义与来源 |
| --- | --- | --- |
| 场景节点数量 | 最多 50,000 | `serialization/scene.ts` 导入/事务校验上限，不是流畅性能承诺 |
| 场景连线数量 | 最多 100,000 | 同上；0.3 使用连线空间索引 |
| 节点位置 | x/y 有限且绝对值 ≤ 1e9 | 数据校验范围，不是该距离下逐像素精度承诺 |
| 节点宽高 | 8～10,000 世界单位 | 数据表达范围；特定交互可有更严格的最小值 |
| 相机缩放 | 0.02～4，即 2%～400% | `zoomAt`/校验限制；fitToContent 自身最大取 1.4 |
| 相机位置 | 有限且绝对值 ≤ 1e9（导入校验） | 直接交互改变相机并不逐帧执行相同校验 |
| 撤销历史 | 最多 100 个事务 | `document/model.ts`，不是 100 个固定大小对象 |
| 渲染分辨率 | `min(devicePixelRatio, 2)` | 创建时设定；不能推断切换显示器后所有 DPR 行为已验收 |
| 视口预留区域 | 四周各 80 CSS 像素 | 索引查询范围；不是额外完整节点常驻保证 |
| 总览 LOD | zoom < 0.2 | 简化矩形批量绘制，减少完整节点与文字 |
| 内容细节/资源请求 | zoom > 0.32 | 展示详细内容并请求可见素材；阈值处与中间段为简化显示 |
| 缩略图最长边 | 最多 768 像素 | `resources/media.ts`；不放大较小源图，不限制源文件字节数 |
| 素材处理并发 | 默认 3 个任务，可配置 | 资源队列中解析与预览处理，不是全 App 网络请求并发 |
| 缩略图缓存预算 | 默认 96 MiB | 96 × 1024² 字节，按宽×高×4 估算；软预算 |
| 缓存条目回收阈值 | 默认 128 项，可配置 | 可见保留项和 pending 项跳过回收，不是绝对上限 |
| 视频封面超时 | 15 秒 | 内部 video 首帧读取；外层任务默认另有 30 秒超时 |
| 资源任务超时 | 默认 30 秒，可配置 | 从出队到解析/解码结束，忽略取消的宿主请求不再占调度槽 |
| 编辑浮层数量 | 一个参数面板、一个内容编辑器/播放器 | 不等于所有视频节点同时播放 |
| 浮层默认宽度 | `min(440, hostWidth - 24)` CSS 像素 | 当前 Web UI 默认值，不是跨平台布局规范 |
| 浮层高度上限 | 520、容器高度 64%、下方剩余空间三者取小 | 初次显示可避让相机；之后展开使用内部空间，不重排节点 |

缓存预算、缓存条目数、并发与任务超时已通过 Options.resources 暴露；其他大部分是实现常量。接入者不能假定可以传入同名配置改变它们。文件大小、业务任务并发、视频输出时长、模型上下文长度不属于引擎性能参数。

## 2. 内存估算

缩略图账面占用采用 RGBA8 的 `width × height × 4`：

- 768×768：2,359,296 字节 = 2.25 MiB；96 MiB 理论容纳约 42 张这种方形缩略图。
- 768×432：1,327,104 字节 ≈ 1.266 MiB；96 MiB 理论容纳约 75 张这种横图。
- 这只是单份像素面的理想估算，不是可同时流畅显示的图片数量。

浏览器可能同时保留解码原图、Canvas 像素、副本、GPU 纹理、图形对象、播放器缓存和 JavaScript 对象。源图会先解码再生成缩略图，因此超大图的解码峰值不受 768 缩略图上限保护。视频解码内存和宿主 Blob 库也不计入 textureBytes。

资源 trim 会保留当前可见资源和未完成任务，因而可能超过 96 MiB/128 项；这是回收策略，不是硬内存隔离。需要严格峰值控制的宿主应在导入前限制像素/文件大小，并提供合适的资源代理或预处理。原始元数据影响自动尺寸，直接把源资源替换成低分辨率缩略图时要考虑尺寸含义。

历史存储以事务补丁为主；长文本和节点增删涉及的顺序数据仍会占用额外内存。100 个事务不意味着固定内存上限。

## 3. 理论复杂度：0.3 代码分析

N 为节点数，E 为边数，V 为可见节点数，K 为变更数，D 为受影响节点关联边数量，R 为资源条目数，S 为数据字节量。空间查询在常见分布下接近对数成本，但重叠严重时会退化。

| 路径 | 主要成本 | 边界 |
| --- | --- | --- |
| 坐标转换/双指相机 | O(1) | 不保证极大坐标逐像素精度 |
| 可见节点准备 | 空间查询 + O(V log V) 排层级 | 大量重叠或总览全图时 V 可接近 N |
| 可见连线/连线命中 | 独立边 RBush 查询 + 候选计算 | 包围盒可能多选；密集跨图连线仍可能接近 E |
| 非结构 apply | 变更对象克隆/校验 + 受影响连线策略检查 | 不再全量复制 Map；数据大小与节点度数仍影响成本 |
| 删除/新增/调整层级 | 邻接查询及变更 + 全量顺序快照/恢复 | 结构操作仍可能 O(N+E)，批次内边变更还需扫描暂存集合 |
| 状态更新 | 文档 O(1)，不重建几何/层级 | 后续按需渲染不等于整个操作 O(1) |
| 导出/验证/载入 | O(N+E+S) 级的克隆校验，加索引构建 | 当前仍可能重复校验；不要逐帧导出 |
| undo/redo | 补丁大小与关联更新；有顺序快照时另需全量顺序恢复 | 已消除恢复顺序时的 includes 嵌套扫描 |
| 资源账面 bytes | O(1) | 不代表浏览器内存采样 |
| 缓存淘汰 | 未超预算 O(1)；超预算 O(R log R) | 可见/pending 项保留，软预算可超出 |
| 媒体元数据回写 | 当前按 assetId 扫描 N 个节点 | 仍有后续增量优化空间 |

普通更新已经增量化，但并非所有操作只依赖可见数量。历史结构快照、载入、导出、自动媒体尺寸查找及全图总览仍需要全量或较大范围工作。

口径：网格排列的文本/工具节点；正常视口平移 150 帧，帧间隔排除前 5 次采样；不是对 10,000 个完整媒体节点同时播放的测试。textureBytes 全为 0，不能用作图片/视频内存证据。loadMs 包含载入及等待两次 rAF，不是纯 JSON 解析时间。drawMs 是 CPU 侧渲染调用的墙钟时间，不等于 GPU 完成时间；采样时读取最近一次 metrics，不能当逐帧 GPU profile。总览数据是单次值，不是分位数。

早期工作区 0.1 报告曾记载 Chromium 145 + ANGLE Metal 的另一组数值，但其 latest.json 链接后来被上述软件渲染结果覆盖。当前目录未提供对应的独立硬件原始文件，本页不将那组历史表格作为可复核的当前性能结论；保留原始历史记录并明确证据缺口。

该历史记录不与下方 Metal 新测直接比较加速倍率：浏览器和 GPU 后端不同。格式上限始终不等于性能认证。

## 5. 指标解释

- `frames`：实例累计实际绘制次数；按需绘制时静止画布不连续增加。播放器或宿主自己的动画仍可能活动。
- `drawMs`：引擎 render 起止的 CPU 侧墙钟时间，包含准备、提交及浮层处理，不是输入到显示延迟。
- `visible`：经视口查询、按缓存层级排序后交给绘制的节点数量，包含拖动预览。
- `visibleEdges`：当前绘制候选连线数量，包含拖动关联边，包围盒查询可能多选。
- `textures`：资源条目数量，包括 pending/失败/无纹理的条目，不是精确 GPU 纹理个数。
- `textureBytes`：已创建缩略图的宽×高×4 累计估算，不是进程内存、显存或原始文件字节数。
- 当前没有公开 API 提供真实 GPU 显存、物理输入延迟或完整进程内存。

## 6. 目标与后续验收

60Hz 的一帧预算约 16.67ms，120Hz 约 8.33ms，只是数学预算。下一轮应在明确设备/场景下约定平移、缩放、拖动、框选和编辑的 p95/p99 门槛，再据此判断通过与否。

建议分别测：100 混合节点；1,000 节点的常见工作场景；10,000 文本/工具节点的压力场景；大量高像素图片和长视频的资源场景。记录视口内数量、总边数、媒体分辨率、总字节数、播放数、编码、运行时长、内存峰值、长任务、失败和恢复。布局规则/重叠程度会影响性能，不能仅报告 N。

已补齐 macOS Playwright Firefox/WebKit 功能回归；当前尚缺：移动真机、Windows/Linux/已安装 Safari/WKWebView、不同 GPU、高 DPR、长时间重媒体、物理输入延迟及上下文丢失后的完整恢复验收。

## 7. 复测命令和证据管理

在本仓库根目录：

```sh
npm ci
npm run build
npx playwright install chromium
# 终端一：生产预览，避免 HMR 干扰
npm run preview -- --port 4317 --strictPort
# 终端二：当前脚本会覆盖 latest.json，请先复制历史原始记录
CANVAS_URL=http://127.0.0.1:4317 npm run benchmark
```

`CANVAS_BROWSER` 指定 Chromium 可执行文件，`CANVAS_HEADED=1` 使用有窗口模式，macOS 可用 `CANVAS_METAL=1` 请求 Metal。这些参数不保证实际后端；必须核对输出的 gpu 字段。示例和脚本使用本仓库实验场；Playwright 默认独占端口 4327，手动 benchmark 默认端口 4317。

发布性能结果时保留不可覆盖的记录，至少附包版本、源码 commit/hash、测试脚本版本、硬件/OS/浏览器、实际 GPU、DPR、场景、样本量、运行参数和统计口径。现有脚本尚不自动记录全部字段，需维护者补充。先验证功能，再测性能；固定软件渲染的功能 E2E 结果不能替代硬件渲染性能测试。

## 8. 0.3.0 硬件实测与对照

正式记录：[quality-1793630840964.json](../benchmarks/results/quality-1793630840964.json)，2026-11-02 14:47:20 UTC。M1 Pro、32 GiB、Darwin 25.6.0、Chrome 156.0.8078.79、ANGLE Metal、1440×960、DPR 1、headless；运行时未并行执行浏览器回归。报告记录运行代码 SHA256、脚本 SHA256、基线 commit 和未提交状态。

| 合成场景 | 最后可见节点 / 候选边 | 平移帧间隔 p95 / p99 | CPU drawMs p95 |
| --- | --- | --- | --- |
| 100 文本节点、99 边 | 8 / 7 | 16.7 / 16.8 ms | 1.2 ms |
| 1,000 文本节点、999 边 | 48 / 40 | 16.7 / 16.8 ms | 3.0 ms |
| 10,000 文本节点、9,999 边 | 48 / 40 | 16.7 / 16.8 ms | 2.7 ms |
| 40 张图片 + 10 个视频封面 | 40 / 0 | 16.7 / 16.8 ms | 2.9 ms |

脚本每场景 150 次 rAF 推进相机；帧间隔丢弃初始热身，drawMs 为最近一次 CPU 绘制指标，不是 GPU profile。媒体是 1200×800 合成 PNG 和仓库 WebM fixture，视频以封面展示，没有并发播放。素材使用真实文件导入、解码与缓存路径；开始采样只要求首个纹理完成，后续解码可发生在采样中。最终纹理账面 65,986,560 字节（约 62.93 MiB），不是 RSS 或显存。500ms 静置采样新增渲染帧为 0。

纯 Document 单节点位置修改另做 10 次热身 + 100 次计时，**场景无连线、不包含 WebGL/空间索引/交互延迟**：

| 场景 | 0.2.4 基线 p95 | 0.3.0 p95 |
| --- | --- | --- |
| 1,000 节点 | 0.838 ms | 0.0072 ms |
| 10,000 节点 | 9.133 ms | 0.0047 ms |

这说明普通事务消除了与全场景大小成比例的拷贝/校验成本，不能解释成用户操作整体快一千倍。基线来自修改前构建的 0.2.4 core；复核可在 d6ce1fc 的独立干净 checkout 构建后提供 dist/core.js。

四项预设门槛均通过：10k 单点事务 p95 < 5ms、混合媒体帧间隔 p95 < 20ms、全部场景 CPU drawMs p95 < 8ms、静置零绘制。门槛只适用于此脚本场景；没有测真实 TVC 长流程、小时级运行、密集全图连线、重媒体同时播放、低端移动设备、物理输入延迟或完整进程内存。
