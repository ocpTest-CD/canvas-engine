| npm run test:cross-browser | 43 次通过、2 次跳过 | 15 个场景 × Chromium/Firefox/WebKit；单 worker；两个跳过是 Firefox/WebKit 无 Chromium CDP 的触摸模拟 |
| npm run check:package | 通过 | 实际 npm tarball 解包、公开入口解析、无 DOM Node 导入 /core、执行 bridge、包文件清单 |
| npm run benchmark:quality | 四项门槛通过 | 本机 M1 Pro + Chrome 156 + Metal，详见性能记录 |
| git diff --check | 通过 | 补丁空白检查 |

不是 43 个独立需求测试，也没有把模拟输入当作真实中文输入法或手机真机验收。浏览器回归覆盖编辑/IME composing 守卫、拖动撤销、保存重开、素材导入/播放、100 混合节点、节点浮层、媒体尺寸、重复销毁、异常回调、快速切换场景及桥接重放。

增量事务另有 250 步确定种子混合操作的 undo/redo 和邻接一致性检查。资源单测使用 mock 解码器；真实图片/视频解码由浏览器用例补足。30 次场景切换验证 URL 创建/释放平衡，不等同小时级无内存泄漏证明。

三浏览器测试发现并修复了 WebKit 实验场持久化问题：保存引用资源的 ArrayBuffer、串行提交，等待真实保存完成后再重开。此修复位于 playground 的宿主存储示例，不把 IndexedDB 加入纯核心。

## 性能证据

[最终原始记录](../benchmarks/results/quality-1793630840964.json)记录代码与脚本 SHA256；[性能说明](performance.md)提供硬限制、软预算、复杂度和复测方式。此记录与浏览器回归分开执行。

- 10,000 节点、9,999 边，正常视口最后可见 48 节点/40 边：平移帧间隔 p95 16.7ms，CPU drawMs p95 2.7ms。
- 40 张图片 + 10 个视频封面：平移 p95 16.7ms，CPU drawMs p95 2.9ms；视频不是同时播放。
- 纯 Document 无连线场景的 10k 单节点编辑 p95：0.2.4 约 9.13ms，0.3.0 约 0.0047ms。这个微基准不包含交互、绘制或空间索引。
- 静置采样新增绘制帧 0。纹理账面约 62.93MiB，不是进程内存或 GPU 显存。

不承诺任意设备一万节点 60 FPS，也不把 50,000 节点/100,000 边的格式上限作为流畅度认证。

## 接入与下一阶段验收

0.3.0 的 [迁移说明](compatibility.md)特别涉及非历史结构变更清空历史、canConnect 覆盖扩大、资源超时与强类型事件。使用 [桥接指南](bridge.md)接 WebView 前，宿主必须实现可信 transport、会话握手和资源管理。

仍须完成：新版 Windows/Linux/macOS 远端 CI、原生 WebView 移动真机、软键盘/系统输入法、低端 GPU、高 DPR、密集全图边、小时级重媒体、上下文丢失恢复以及下游桌面 App 集成。新增 CI 定义只代表检查已经配置，不计作远端通过。

本报告记录提交前完成的本机验收。源码提交与推送不等于 npm 发布或桌面 App 更新；远端 CI 以对应 commit 的 GitHub Actions 结果为准。
